# morphing — Context

## What
The `GaussianSplatMorpher` runtime component (`Runtime/GaussianSplatting/Morph/GaussianSplatMorpher.cs`) and `GaussianMorphMap` asset (`Runtime/GaussianSplatting/Morph/GaussianMorphMap.cs`), plus their editor tooling (`Editor/GaussianSplatting/Morph/GaussianMorphMapBuilderWindow.cs`, `Editor/GaussianSplatting/Morph/GaussianMorphMapBuilder.cs`, `Editor/GaussianSplatting/Morph/GaussianSplatMorpherEditor.cs`, `Editor/GaussianSplatting/GaussianSplatRendererEditor.cs`) — the package-side machinery for morphing between two `GaussianSplatAsset`s on a shared splat correspondence map. Supports both compressed (chunked) and uncompressed (HighQuality, no chunk data) source assets, in any combination. This target owns the package itself, not its consumers — the Timeline-side usage in the main project lives in the [[gaussian-morphing]] target (`KitchenOfMemories_Unity6` repo), which reaches this package only through the git package dependency, never by editing it directly.

Note: this target's history was split across two Flow roots (`.claude/flow/` sessions 1-3, then `.flow/` sessions 4-5) from a mid-project skill-path change — sequential, not divergent. Merged into this single context at the point of discovery (2026-07-14); `.claude/flow/morphing.*` retired.

## Why
The correspondence search (nearest-neighbor matching between two splat sets) is computationally expensive — not feasible to run at runtime on Quest. It must be precomputed offline in the editor and baked into a `GaussianMorphMap` asset; runtime only does a cheap per-frame lerp between already-matched pairs. Strict 1:1 uniqueness in that correspondence isn't required; convergence (every splat has a destination to move toward) is the real constraint — a GPU-dispatched nearest-neighbor remainder pass (not a CPU loop, which stalls at real asset scale) resolves collisions left over after the main round-based matching, accepting duplicate matches over unmatched splats.

The morph's output position/scale buffers are always written in a fixed packed layout (Norm11 position, rot+Norm6-padded scale) by the compute shader, independent of the source assets' import formats — lets the morph blend any combination of compressed/uncompressed sources without per-format kernel variants, at the cost of always declaring a distinct "morph output format" to the renderer rather than passing a source asset's format through unmodified. `SplatMorph.compute`'s `EncodeNorm6`/`DecodeNorm6` previously used the wrong bit layout (5/6/5 instead of canonical 6/5/5) — a pre-existing latent bug, unmasked (not introduced) when the format declaration was later made honest; fixed to match `RuntimeSplatProcessing.EncodeFloat3ToNorm655`/`DecodePacked_6_5_5`.

`GaussianSplatMorpher` originally only supported a pair of assets assigned at edit time, with no public way for external code (a runtime Timeline mixer) to assign a *new* pair — `SwapAssets()` only swapped the existing one. This blocked [[gaussian-morphing]]'s morph-pair Timeline clip case for a full session until `SetAssets(left, right, map)` was added here, since the consuming project can't edit a git-URL package dependency directly; any fix has to land at this source repo first, then flow back via the existing dependency.

Two correctness bugs surfaced once `SetAssets` was actually exercised from Timeline: (1) `GaussianMorphMap` stored only splat counts, no asset identity — `MapIsSwapped()`'s count-based heuristic couldn't disambiguate orientation whenever both assets had equal/similar counts, causing morph playback to invert and the fix to not persist across clip restarts (`MapIsSwapped()` recomputes every `Setup()`, independent of any manual swap). Fixed by storing asset GUIDs on the map at build time and comparing by identity, falling back to the count heuristic only for legacy pre-fix maps. (2) `SetAssets`'s null-guard only checked `assetLeft`/`assetRight`, not `morphMap` — once the Timeline mixer started calling `SetAssets` with a partial set (assets assigned, map not yet built, to keep the morpher's Inspector fields in sync with clip authoring state), `Setup()` ran through to `BuildIndexBuffer()` → `MapIsSwapped()` and dereferenced the null map. Fixed by extending the same guard to all three fields, matching `OnEnable`'s existing all-three check.

A separate, unrelated editor bug was found and fixed alongside this work: `GaussianSplatRendererEditor.OnGetFrameBounds()` read `gs.asset.boundsMin`/`boundsMax` without checking `gs.asset` for null — while `GaussianSplatMorpher` has taken over a renderer via `SetExternalBuffers`, `gs.asset` is legitimately null (the renderer is driven by external buffers, not its own asset), and pressing Frame Selected (F) in that state threw `NullReferenceException` every time.

## Where
- `Runtime/GaussianSplatting/Morph/GaussianSplatMorpher.cs` — `SetAssets(left, right, map)` (public) is the entry point for runtime asset-pair reassignment; mirrors `SwapAssets()`'s rebuild pattern (`ReleaseGpuResources()` + `Setup()`) when called while enabled with a valid new pair, tears down to idle (matching `OnEnable`'s null-guard) when any of the three (assetLeft/assetRight/morphMap) is missing. `MapIsSwapped()` (called from `BuildIndexBuffer()` inside `Setup()`) resolves orientation by asset-GUID identity when the map carries one, falling back to splat-count comparison only for maps built before that field existed. `BindBuffersForT`'s blend branch declares the output format explicitly (Norm11 pos | Norm6Padded(=4, morph-output-only, not a real `VectorFormat` enum value) scale | passthrough SH) rather than reusing source asset format bits. `AllocateOutputBuffers` allocates at fixed strides (posStride=4, otherStride=8 bytes) matching that output layout, not derived from source asset strides — shStride still derives from source A (SH is a format-dependent passthrough copy). `AccumulateAssetBounds` falls back to `asset.boundsMin/boundsMax` when an asset has no chunk data (uncompressed case) instead of skipping that asset's bounds contribution. `DispatchMorph` always binds `_ChunksA`/`_ChunksB` (falling back to the position buffer as a dummy) even when there's no real chunk buffer, since Unity's compute shader validation requires every declared shader resource to be bound regardless of whether the kernel's runtime branch reads it.
- `Runtime/GaussianSplatting/Morph/GaussianMorphMap.cs` — `leftAssetGuid`/`rightAssetGuid` string fields, set at build time via `AssetDatabase.AssetPathToGUID`. Empty on legacy maps (falls back to splat-count heuristic).
- `Editor/GaussianSplatting/Morph/GaussianMorphMapBuilder.cs` — correspondence search: round-based one-to-one matching (`kMaxMatchRounds = 8`, greedy nearest-distance-wins collision resolution via `ResolveOneToOne`) + GPU-dispatched remainder resolution (`ResolveRemainderOnGpu`, duplicates allowed, guarantees convergence not uniqueness) for leftovers after the round cap. CPU decode helpers for positions/colors from asset layer data (compressed and uncompressed). Distance metric itself lives in the compute shader (see below).
- `Editor/GaussianSplatting/Morph/GaussianMorphMapBuilderWindow.cs` — editor window UI; `Open(left, right)` overload pre-populates fields (converges into the same `StartBuild()`/`SaveAsset()` flow as the parameterless menu path). `m_ColorWeight` slider (0=position only, 1=color only) is the only user-facing control over match weighting, passed through as `colorWeight`/`posWeight = 1 - colorWeight` to the builder. `SaveAsset()` stamps `leftAssetGuid`/`rightAssetGuid` alongside splat counts.
- `Editor/GaussianSplatting/Morph/GaussianSplatMorpherEditor.cs` — inspector; "Build Morph Map…" button next to asset fields (disabled until both set), opens the builder window pre-filled — second creation path converging into the existing flow.
- `Editor/GaussianSplatting/GaussianSplatRendererEditor.cs` — `OnGetFrameBounds()`'s early-return guard also checks `!gs.asset`, alongside `!gs`/`!gs.HasValidRenderSetup` — `gs.asset` is legitimately null while a `GaussianSplatMorpher` has taken over via `SetExternalBuffers`.
- `Shaders/SplatCorrespondence.compute` — `FindBestMatch` kernel, one thread per L splat, brute-force O(n·m) search against all R candidates. Distance = `posWeight * |Δposition|² + colWeight * |Δcolor|²` — a single unnormalized scalar combining both terms directly. Positions are pre-normalized into a shared [0,1] bounding box before upload; colors are raw RGBA, not normalized relative to position's scale. Reused for both the round loop and remainder resolution.
- `Shaders/SplatMorph.compute` — per-pair lerp kernel (`MorphSplats`/`CopyUnmatchedA`/`CopyUnmatchedB`). `OUT_OTHER_STRIDE`=8 (4 rot + 4 Norm6-padded scale), fixed regardless of source format. Position always written via `EncodeNorm11`. `EncodeNorm6`/`DecodeNorm6` pack as canonical 6/5/5 (x:6bits@0, y:5bits@6, z:5bits@11), matching `RuntimeSplatProcessing.EncodeFloat3ToNorm655` and `GaussianSplatting.hlsl`'s `DecodePacked_6_5_5`.
- `Shaders/GaussianSplatting.hlsl` — `VECTOR_FMT_6_PADDED` (=4) is a morph-output-only format constant (never a real serialized asset format), signaling Norm6 bit layout at a 4-byte-aligned stride instead of the tightly-packed 2-byte stride real Norm6 assets use.
- `Runtime/GaussianSplatting/GaussianSplatRenderer.cs` — `SetExternalBuffers`'s chunk-buffer swap guard also triggers dummy-buffer creation when `m_GpuChunks` was never initialized and the incoming `chunks` is also null (`null != null` alone misses this case).
- GUID resolution in `MapIsSwapped()` is wrapped in `#if UNITY_EDITOR` (`AssetDatabase` is editor-only) — at runtime in a build this always falls through to the splat-count heuristic.
- Legacy `GaussianMorphMap` assets built before the GUID fix have empty GUID fields and must be rebuilt via the Morph Map Builder window to get identity-based orientation detection.

## When

**Future**
- Correspondence match quality (color-weight slider) under active investigation (2026-07-14): at `colorWeight=1` (posWeight=0), position is ignored entirely, letting same-colored splats from spatially distant clusters match to each other — visually, whole clusters "swap places" during blend instead of moving coherently. User's target spec: weight=0 → pure position, weight=1 → pure color (cross-cluster swaps acceptable at this extreme), weight=0.5 → position and color should carry genuinely equal influence, meaning a swap shouldn't win just because color favors it while position strongly opposes it. Root cause identified: `SplatCorrespondence.compute`'s distance is an unnormalized `posWeight*|Δpos|² + colWeight*|Δcolor|²` — position and color deltas live on uncalibrated, non-comparable scales, so the slider isn't a true linear blend between two comparable metrics; a fix needs to normalize both terms onto comparable scales before weighting (spatial-gating was considered and rejected — it would prevent legitimate long-range matches at weight=1, violating the spec). Not yet implemented — Tag Team investigation into the current implementation's exact assumptions is where this picks up next.
- Splat-count inflation bug in `GaussianMorphMapBuilder.ResolveRemainderOnGpu` (matchedCount can exceed `max(nL,nR)` when both sides have leftovers after the round cap, confirmed live at 303862 vs 262144 on `Car_House_Morph`) — explicitly deprioritized by user, no visible symptom, not worth fixing unless one surfaces.
- Custom Timeline track for keying `m_AssetLeft`/`m_AssetRight`/`m_MorphMap` (Unity's native object-reference animation curves don't support ScriptableObject PPtr fields) — design direction set (belongs in this package, not `timeline-controller`), user implementing personally, not a tracked Claude task.
- No automated test coverage exists for the morph path (manual in-editor/live-buffer verification only) — flagged, not actioned.
- Legacy `GaussianMorphMap` assets built before the GUID fix will silently keep using the splat-count fallback until individually rebuilt — known migration path, not an active task.
