# morphing — Context

## What
The `GaussianSplatMorpher` runtime component (`Runtime/GaussianSplatting/Morph/GaussianSplatMorpher.cs`) and `GaussianMorphMap` asset (`Runtime/GaussianSplatting/Morph/GaussianMorphMap.cs`), plus their editor tooling (`Editor/GaussianSplatting/Morph/GaussianMorphMapBuilderWindow.cs`, `Editor/GaussianSplatting/Morph/GaussianMorphMapBuilder.cs`, `Editor/GaussianSplatting/Morph/GaussianSplatMorpherEditor.cs`, `Editor/GaussianSplatting/GaussianSplatRendererEditor.cs`) — the package-side machinery for morphing between two `GaussianSplatAsset`s on a shared splat correspondence map. Supports both compressed (chunked) and uncompressed (HighQuality, no chunk data) source assets, in any combination. This target owns the package itself, not its consumers — the Timeline-side usage in the main project lives in the [[gaussian-morphing]] target (`KitchenOfMemories_Unity6` repo), which reaches this package only through the git package dependency, never by editing it directly.

Note: this target's history was split across two Flow roots (`.claude/flow/` sessions 1-3, then `.flow/` sessions 4-5) from a mid-project skill-path change — sequential, not divergent. Merged into this single context at the point of discovery (2026-07-14); `.claude/flow/morphing.*` retired.

## Why
The correspondence search (nearest-neighbor matching between two splat sets) is computationally expensive — not feasible to run at runtime on Quest. It must be precomputed offline in the editor and baked into a `GaussianMorphMap` asset; runtime only does a cheap per-frame lerp between already-matched pairs. Strict 1:1 uniqueness in that correspondence isn't required; convergence (every splat has a destination to move toward) is the real constraint — a GPU-dispatched nearest-neighbor remainder pass (not a CPU loop, which stalls at real asset scale) resolves collisions left over after the main round-based matching, accepting duplicate matches over unmatched splats.

The morph's output position/scale buffers are always written in a fixed packed layout (Norm11 position, rot+Norm6-padded scale) by the compute shader, independent of the source assets' import formats — lets the morph blend any combination of compressed/uncompressed sources without per-format kernel variants, at the cost of always declaring a distinct "morph output format" to the renderer rather than passing a source asset's format through unmodified. `SplatMorph.compute`'s `EncodeNorm6`/`DecodeNorm6` previously used the wrong bit layout (5/6/5 instead of canonical 6/5/5) — a pre-existing latent bug, unmasked (not introduced) when the format declaration was later made honest; fixed to match `RuntimeSplatProcessing.EncodeFloat3ToNorm655`/`DecodePacked_6_5_5`.

`GaussianSplatMorpher` originally only supported a pair of assets assigned at edit time, with no public way for external code (a runtime Timeline mixer) to assign a *new* pair — `SwapAssets()` only swapped the existing one. This blocked [[gaussian-morphing]]'s morph-pair Timeline clip case for a full session until `SetAssets(left, right, map)` was added here, since the consuming project can't edit a git-URL package dependency directly; any fix has to land at this source repo first, then flow back via the existing dependency.

Two correctness bugs surfaced once `SetAssets` was actually exercised from Timeline: (1) `GaussianMorphMap` stored only splat counts, no asset identity — `MapIsSwapped()`'s count-based heuristic couldn't disambiguate orientation whenever both assets had equal/similar counts, causing morph playback to invert and the fix to not persist across clip restarts (`MapIsSwapped()` recomputes every `Setup()`, independent of any manual swap). Fixed by storing asset GUIDs on the map at build time and comparing by identity, falling back to the count heuristic only for legacy pre-fix maps. (2) `SetAssets`'s null-guard only checked `assetLeft`/`assetRight`, not `morphMap` — once the Timeline mixer started calling `SetAssets` with a partial set (assets assigned, map not yet built, to keep the morpher's Inspector fields in sync with clip authoring state), `Setup()` ran through to `BuildIndexBuffer()` → `MapIsSwapped()` and dereferenced the null map. Fixed by extending the same guard to all three fields, matching `OnEnable`'s existing all-three check.

`ReadFloat`/`WriteFloat`/`WriteUInt` (chunk-bounds helper methods) previously allocated a fresh `byte[4]` via `System.BitConverter` on every call — millions of GC.Alloc calls inside a single `OnEnable()` at real asset scale. Rewritten to direct bit-shift math (unsafe pointer reinterpret for float↔uint), zero heap allocation per call.

`WarmUpStep`/`CancelWarmUp` (a resumable per-stage/per-chunk state machine, `WarmStage` enum + `m_Warm*` fields) lets a Timeline mixer spread the GPU upload + chunk-bounds computation across multiple frames while a preceding clip still plays, instead of paying the full `Setup()` cost synchronously at `OnEnable()`. Hard-guarded to no-op (and cancel) if `enabled == true`, since the upload/index-buffer/output-buffer calls it drives write into the SAME fields the live/active pair uses — running warm-up while enabled would corrupt on-screen state. `OnEnable()` and `SetAssets()` both check for and consume a matching completed warm state (bind buffers only, skip `Setup()`) instead of redoing the full synchronous rebuild — but since both run for the same pair-change activation (not one-or-the-other: `SetAssets()` is called directly by a mixer, then `OnEnable()` fires moments later when Unity processes `enabled=true`), each independently trying to consume the same warm state raced — whichever ran first cleared it, the second found nothing and silently redid the full rebuild anyway, defeating the optimization while looking correct in isolated review. Fixed via `m_BoundThisActivation`: set true by whichever of the two does the actual binding work first for a given activation, checked by whichever runs second, which then returns immediately without calling `Setup()` at all. A third `Setup()`/`ReleaseGpuResources()` call site in `SwapAssets()` was deliberately NOT given the same treatment — nothing calls `SwapAssets()` in a way that could race with warm-up (confirmed via audit) — worth revisiting only if that changes.

A separate, unrelated editor bug was found and fixed alongside this work: `GaussianSplatRendererEditor.OnGetFrameBounds()` read `gs.asset.boundsMin`/`boundsMax` without checking `gs.asset` for null — while `GaussianSplatMorpher` has taken over a renderer via `SetExternalBuffers`, `gs.asset` is legitimately null (the renderer is driven by external buffers, not its own asset), and pressing Frame Selected (F) in that state threw `NullReferenceException` every time.

**Session 7 rainbow-splat-corruption root cause**: a real, previously-latent bug distinct from the earlier bonsai/car-model rainbow-quad case (that one was a deterministic MorphMap orientation swap; this one was attempt-to-attempt inconsistent, occurring on the no-MorphMap/all-unmatched path). Root cause: none of `SplatMorph.compute`'s three kernels (`MorphSplats`/`CopyUnmatchedA`/`CopyUnmatchedB`) ever wrote the output SH buffer (`_OutSH`) — a stale comment falsely claimed a `CopyBuffer` fallback existed in `GaussianSplatMorpher.cs`'s `OnEnable`, but no such call was ever present. The buffer was allocated at the correct size but left as whatever uninitialized GPU memory the fresh `GraphicsBuffer` allocation happened to contain, which was then read as real per-splat SH coefficients at render time (`ShadeSH` in `SplatUtilities_FidelityFX.compute`) — explaining the color-only (not position) corruption, attempt-to-attempt inconsistency (different leftover GPU memory each allocation), and variable severity (5%-50% of splats depending on what garbage happened to be there). Root-caused via live GPU buffer introspection in the KitchenOfMemories consumer project (unity-mcp, port 7890) rather than static source reading alone — buffer contents were read directly off a live, reproducing `GaussianSplatMorpher` instance mid-corruption. Fixed by deliberately zero-clearing `_OutSH` at allocation (chosen over implementing real per-region SH copy/lerp, to stay minimal and match the existing "TODO: proper SH lerp" deferred intent rather than half-implementing it) — verified end-to-end (package-cache test fix confirmed the symptom disappears, then the same fix landed properly in this source repo, verified again, committed and pushed).

**Session 6 (2026-07-14/15) — the correspondence-quality investigation, in order of what actually held up:**
1. Root cause of visible cluster-swapping at any non-trivial `colorWeight`: `SplatCorrespondence.compute`'s original distance was an unnormalized `posWeight*|Δpos|² + colWeight*|Δcolor|²` — intra-cluster position deltas (~0.01-0.07) are 1-2 orders of magnitude smaller than color's full contested range (~0-3), so color could out-vote a correct same-cluster match well before `colorWeight` reached 1. Confirmed both analytically and against real 294912-splat data (13/20 random samples showed the swap signature: large position jump + near-zero color delta).
2. Fixed via per-splat z-score normalization (2-pass: mean/stddev, then z-score each axis before blending) — confirmed 0/20 swap-signature samples post-fix vs 13/20 pre-fix, same real asset, same sampled indices.
3. z-score fix had a side effect: `ResolveOneToOne`'s cross-splat collision arbitration compared z-scored `bestDist` values, which are per-splat-relative and not comparable across different L splats — this let duplicate-match fan-out explode (one L splat matched to 5+ different R destinations, confirmed via a new `AnalyzeDuplicates` diagnostic), which independently produces a visually identical "splats tearing apart" symptom at runtime (`SplatMorph.compute`'s `MorphSplats` is one-thread-per-pairs-entry — a duplicated L index produces multiple output splats reading the same source but interpolating toward different destinations). Fixed by having `FindBestMatch` output both the z-scored blend (selection) and the raw distance to the chosen candidate (cross-splat arbitration) — `ResolveOneToOne` switched to comparing the raw value.
4. z-score itself was later replaced with **min-max squash** (per-splat min/max instead of mean/stddev, normalize to [0,1] before blending) — z-score normalizes relative to the pool MEAN, so a candidate merely "central"/average across the whole R set could look best for a huge number of unrelated L splats; measured at 9.2% distinct-candidate ratio on a real 294912-splat asset (mass convergence onto ~27k R splats). Min-max is monotonic in the raw distance so it can never reorder candidates — this is the current, final distance metric in `FindBestMatch`/`FindTopKMatches`.
5. **Named the root symptom**: "hubness" — a formally studied phenomenon in nearest-neighbor search over metric/embedding spaces where some points become disproportionately popular k-NN targets ("hubs") while others become "antihubs" (rarely/never chosen) — this session's own "popular R splat with fan-out 11562+" observation is a direct instance, not project-specific.
6. **Sinkhorn (entropic-regularized optimal transport)** was designed, partially implemented (sparse k-NN-truncated cost matrix from `FindTopKMatches`), and then fully abandoned — hit genuine numerical instability at ~300k scale (not an implementation bug in isolation). All Sinkhorn code (kernels, dispatcher, diagnostics) was removed from the codebase; do not re-attempt without a different numerical approach.
7. **Spatial probe partitioning** (`BuildViaProbes`) was built as a working alternative: splits the global search into many small local sub-problems via a shared position-only grid, resolved per-probe on GPU. Confirmed working end-to-end (real distinct match counts, no remainder-fallback masking) but still showed severe R-splat fan-out until a normalization bug was fixed (bucket resolution was using raw world-space positions instead of each cloud's independently-normalized [0,1]³ positions).
8. **Three candidates were identified and two implemented on separate branches** to compare against the round-based/probe baselines, specifically targeting hubness: (a) **mutual/symmetric top-K matching** (`BuildViaMutualTopK`, branch `symmmetric-greedy`) — a pair is only accepted when each side has the other in its own top-32 list; 34.1% matched (100576/294912) on a real asset, no remainder fallback. (b) **GS-Matching** (`BuildViaGaleShapley`, branch `gale`) — ported from the actual paper (Yu et al., arXiv:2412.04855) after an initial draft wrongly implemented classic proposer/rejection deferred acceptance; the real algorithm is a mutual-best iterative filter with a scarcity-based priority (V_NC/"noise count"), not proposer/rejection. Gave the best match ratio of the two (50%) but is currently slow (re-dispatches the full-width GPU search every round instead of shrinking with the active pool — not yet optimized). (c) Secondary/hubness-corrected distance (Local Scaling, Mutual Proximity, Shared Nearest Neighbors) — researched in depth, understood as a rescaling MODIFIER applicable on top of any matching algorithm, not a standalone algorithm; never implemented.
9. **Major negative result, not yet resolved**: despite both (a) and (b) being purpose-built against hubness/mass-convergence via mutual-agreement stable matching, and (b) especially having a formal stability guarantee, **GS-Matching still does NOT solve the visual clustering/collapse symptom** the user sees during morph playback. This casts real doubt on the session's core working hypothesis — that independent-argmin hubness was THE root cause of visible clustering — since a stable-matching algorithm purpose-built against exactly that failure mode still exhibits it. Whether the mutual-top-K candidate ALSO still shows clustering has not yet been directly re-checked (only its lower match ratio was measured).
10. A distance-threshold hard-cap (present in the project's own prior/original implementation, `feel3x/Gaussian_Splat_Morpher`, confused mid-session for an independent 4th candidate before being correctly identified as this project's own history) was explicitly considered and rejected — it structurally conflicts with the non-negotiable 100%-matched requirement (a hard cutoff by design produces unmatched/faded splats), not just a quality tradeoff.
11. `symmmetric-greedy` and `gale` both forked from an old point on `main` (`a8f2625`), missing `main`'s later stereo-matrix fix (`aa9e932`) — this independently caused an HMD flat-rendering regression, diagnosed and fixed as its own target (see [[rendering-regression]]). Both branches were subsequently merged back together onto a branch named `gale` (confusingly reusing the name) with both `BuildViaMutualTopK` and `BuildViaGaleShapley` coexisting as independent window-toggleable options — real merge conflicts (both branches added a method at the same insertion point) resolved by keeping both methods side by side; compiles clean. The merge is resolved in the working tree but not yet committed.

## Where
- `Runtime/GaussianSplatting/Morph/GaussianSplatMorpher.cs` — `ReadFloat`/`WriteFloat`/`WriteUInt` use bit-shift math, no `BitConverter`/heap allocation. `WarmUpStep(left, right, map, msBudget)`/`CancelWarmUp()`/`WarmStage` enum/`m_Warm*` fields drive the resumable multi-frame warm-up; `m_BoundThisActivation` guards `OnEnable()`/`SetAssets()` against double-consuming the same completed warm state. `SetAssets(left, right, map)` (public) is the entry point for runtime asset-pair reassignment; mirrors `SwapAssets()`'s rebuild pattern (`ReleaseGpuResources()` + `Setup()`) when called while enabled with a valid new pair, tears down to idle (matching `OnEnable`'s null-guard) when any of the three (assetLeft/assetRight/morphMap) is missing. `MapIsSwapped()` (called from `BuildIndexBuffer()` inside `Setup()`) resolves orientation by asset-GUID identity when the map carries one, falling back to splat-count comparison only for maps built before that field existed. `BindBuffersForT`'s blend branch declares the output format explicitly (Norm11 pos | Norm6Padded(=4, morph-output-only, not a real `VectorFormat` enum value) scale | passthrough SH) rather than reusing source asset format bits. `AllocateOutputBuffers` allocates at fixed strides (posStride=4, otherStride=8 bytes) matching that output layout, not derived from source asset strides — shStride still derives from source A (SH is a format-dependent passthrough copy). `AccumulateAssetBounds` falls back to `asset.boundsMin/boundsMax` when an asset has no chunk data (uncompressed case) instead of skipping that asset's bounds contribution. `DispatchMorph` always binds `_ChunksA`/`_ChunksB` (falling back to the position buffer as a dummy) even when there's no real chunk buffer, since Unity's compute shader validation requires every declared shader resource to be bound regardless of whether the kernel's runtime branch reads it.
- `Runtime/GaussianSplatting/Morph/GaussianMorphMap.cs` — `leftAssetGuid`/`rightAssetGuid` string fields, set at build time via `AssetDatabase.AssetPathToGUID`. Empty on legacy maps (falls back to splat-count heuristic).
- `Editor/GaussianSplatting/Morph/GaussianMorphMapBuilder.cs` — correspondence search: round-based one-to-one matching (`kMaxMatchRounds = 8`, greedy nearest-distance-wins collision resolution via `ResolveOneToOne`) + GPU-dispatched remainder resolution (`ResolveRemainderOnGpu`, duplicates allowed, guarantees convergence not uniqueness) for leftovers after the round cap. CPU decode helpers for positions/colors from asset layer data (compressed and uncompressed). Distance metric itself lives in the compute shader (see below).
- `Editor/GaussianSplatting/Morph/GaussianMorphMapBuilderWindow.cs` — editor window UI; `Open(left, right)` overload pre-populates fields (converges into the same `StartBuild()`/`SaveAsset()` flow as the parameterless menu path). `m_ColorWeight` slider (0=position only, 1=color only) is the only user-facing control over match weighting, passed through as `colorWeight`/`posWeight = 1 - colorWeight` to the builder — confirmed threaded correctly through both `BuildViaMutualTopK` and `BuildViaGaleShapley`. `m_UseSpatialProbes`/`m_UseMutualTopK`/`m_UseGaleShapley` toggles branch `StartBuild()` to the respective build method (plain round-based `Build()` is the final else); each has its own main-thread GPU dispatcher class (`MainThreadDispatcher`/`MainThreadProbeDispatcher`/`MainThreadTopKDispatcher`/`MainThreadGaleShapleyDispatcher`), same flag+`ManualResetEventSlim` marshalling pattern, serviced from `OnEditorUpdate`. `m_UseRemainderFallback` toggle (round-based only) — when off, reports the round loop's own unpadded match quality instead of silently filling gaps, a diagnostic to see ground-truth quality without fallback masking it. `SaveAsset()` stamps `leftAssetGuid`/`rightAssetGuid` alongside splat counts.
- `Editor/GaussianSplatting/Morph/GaussianSplatMorpherEditor.cs` — inspector; "Build Morph Map…" button next to asset fields (disabled until both set), opens the builder window pre-filled — second creation path converging into the existing flow. Now also shows a "Matched / Unmatched" readout (`{matched} / {unmatchedLeft.Length} ({pct}% matched)`) directly under the assigned `GaussianMorphMap` field, using the map's own `MatchedCount`/`splatCountLeft`/`unmatchedLeft` — lets the count be checked without opening the builder window separately.
- `Runtime/GaussianSplatting/GaussianSplatRenderer.cs` — `m_SplatScale`/`m_OpacityScale` `[Range]` minimums lowered from 0.1/0.05 to 0 (splats can now be fully hidden via scale/opacity alone). `s_DebugCountersEnabled`/`m_LastPostCullCount` (editor-only, `#if UNITY_EDITOR`) feed a Scene-view splat-count overlay (input vs. post-cull-compute survivor count) via `AsyncGPUReadback` reusing the buffer already allocated for `CalcViewData`'s cull — no extra GPU buffer needed. A fragment-level survivor counter was also prototyped then fully removed (conceptually flawed — no "splat" unit exists at the fragment/pixel stage).
- `Editor/GaussianSplatting/GaussianSplatRendererEditor.cs` — `OnGetFrameBounds()`'s early-return guard also checks `!gs.asset`, alongside `!gs`/`!gs.HasValidRenderSetup` — `gs.asset` is legitimately null while a `GaussianSplatMorpher` has taken over via `SetExternalBuffers`.
- `Shaders/SplatCorrespondence.compute` — `FindBestMatch` kernel, one thread per L splat, brute-force O(n·m) search against all R candidates. Distance is now a per-splat **min-max squashed** blend (each L splat's own pos/color distances normalized to [0,1] against its own candidate pool before weighting) — replaced the original unnormalized scalar (fixed via z-score, then min-max; z-score itself was found to let "pool-central" candidates dominate, see Why). `FindTopKMatches` kernel — same distance metric, returns the best 32 candidates per L splat instead of collapsing to one; used by `BuildViaMutualTopK` and diagnostics, not by the original round-based `Build()`. `AssignToSpatialProbes`/`ResolveProbeBuckets` kernels back `BuildViaProbes`. Sinkhorn kernels were added then fully removed — do not reintroduce without solving its numerical instability at ~300k scale first.
- `Shaders/SplatGaleShapley.compute` (new, branch `gale`) — self-contained, does not share kernels/layout with `SplatCorrespondence.compute`. `CountCandidatesBelowThreshold` (the paper's V_NC/noise-count scarcity signal) + `BestRemaining` (mutual-best candidate search against an `_ActiveR`/`_ActiveL` mask, dispatched twice per round with L/R swapped).
- `Editor/GaussianSplatting/Morph/GaussianMorphMapBuilder.cs` — `Build()` (original round-based, `ResolveOneToOne`/`ResolveRemainderOnGpu`) is the baseline. `BuildViaProbes` (spatial-probe partitioning, swappable `IProbeGridStrategy`/`IProbeResolutionStrategy`). `BuildViaMutualTopK` (branch `symmmetric-greedy`, `ITopKDispatcher`, `ResolveMutualTopK` — mutual top-32 agreement, no remainder fallback). `BuildViaGaleShapley` (branch `gale`, `IGaleShapleyDispatcher` — mutual-best iterative filter per the actual GS-Matching paper, scarcity-priority resolution order, own nearest-neighbor fallback for leftovers, not `ResolveRemainderOnGpu`). Diagnostics: `SampleMatchQuality` (position/color delta per sampled pair — the primary swap-detection tool), `AnalyzeDuplicates`/`TopDuplicatedRight` (fan-out/duplicate-match diagnostics), `AnalyzeCandidateCollisions` (distinct-candidate ratio — the hubness/mass-convergence measurement).
- `Shaders/SplatMorph.compute` — per-pair lerp kernel (`MorphSplats`/`CopyUnmatchedA`/`CopyUnmatchedB`). `OUT_OTHER_STRIDE`=8 (4 rot + 4 Norm6-padded scale), fixed regardless of source format. Position always written via `EncodeNorm11`. `EncodeNorm6`/`DecodeNorm6` pack as canonical 6/5/5 (x:6bits@0, y:5bits@6, z:5bits@11), matching `RuntimeSplatProcessing.EncodeFloat3ToNorm655` and `GaussianSplatting.hlsl`'s `DecodePacked_6_5_5`. None of the three kernels write `_OutSH` — comment corrected (session 7) to state this plainly and reference why (see Why's rainbow-corruption entry); `GaussianSplatMorpher.cs`'s `AllocateOutputBuffers` now deliberately zero-clears `_OutSH` right after allocation instead of leaving it as uninitialized GPU memory.
- `Editor/GaussianSplatting/Morph/GaussianMorphMapBuilderWindow.cs` (session 7 UI redesign) — the four algorithm bool toggles (`m_UseSpatialProbes`/`m_UseMutualTopK`/`m_UseGaleShapley`) replaced with one `CorrespondenceAlgorithm` enum dropdown (RoundBased/SpatialProbes/MutualTopK/GaleShapley); `m_UseRemainderFallback` renamed to `m_ForceMatchPass` (same semantics, still round-based-only). All diagnostic buttons moved under a `m_ShowDiagnostics` foldout, split into "Analyze Morphmap" (Sample Match Quality, Analyze Duplicates, Top Duplicated R Splats — operate on a saved `GaussianMorphMap`) and "Analyze Morph Candidates" (Analyze Candidate Collisions/RoundBased-only, Verify Top-K Matches Kernel/MutualTopK-only, Analyze Spatial Probe Occupancy/SpatialProbes-only — operate on raw pre-build asset pairs, algorithm-tied buttons hidden not just disabled when their algorithm isn't selected). `StartBuild()`'s dispatch switched from if/else-if on bools to a switch on the enum. Compiles clean; not yet visually clicked-through in the actual Editor window (compile-verification only).
- `Editor/GaussianSplatting/Morph/GaussianSplatMorpherEditor.cs` — the Matched/Unmatched readout (added session 6) has a confirmed display bug: divides by `currentMap.splatCountLeft` without calling `MapIsSwapped()`, so a swapped-orientation map shows an impossible percentage (e.g. 131.5%) — same root cause the GUID-identity fix (session 5) solved for GPU buffer setup, but this readout was never updated to use that check. Confirmed unrelated to the rainbow-quad/rainbow-splat bugs (both session 7 and the bonsai/car-model case) — a separate, still-unfixed bug.
- `Shaders/GaussianSplatting.hlsl` — `VECTOR_FMT_6_PADDED` (=4) is a morph-output-only format constant (never a real serialized asset format), signaling Norm6 bit layout at a 4-byte-aligned stride instead of the tightly-packed 2-byte stride real Norm6 assets use.
- `Runtime/GaussianSplatting/GaussianSplatRenderer.cs` — `SetExternalBuffers`'s chunk-buffer swap guard also triggers dummy-buffer creation when `m_GpuChunks` was never initialized and the incoming `chunks` is also null (`null != null` alone misses this case).
- GUID resolution in `MapIsSwapped()` is wrapped in `#if UNITY_EDITOR` (`AssetDatabase` is editor-only) — at runtime in a build this always falls through to the splat-count heuristic.
- Legacy `GaussianMorphMap` assets built before the GUID fix have empty GUID fields and must be rebuilt via the Morph Map Builder window to get identity-based orientation detection.
