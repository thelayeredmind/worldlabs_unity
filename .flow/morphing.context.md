# morphing — Context

## What
The `GaussianSplatMorpher` runtime component (`Runtime/GaussianSplatting/Morph/GaussianSplatMorpher.cs`) and `GaussianMorphMap` asset (`Runtime/GaussianSplatting/Morph/GaussianMorphMap.cs`), plus their editor tooling (`Editor/GaussianSplatting/Morph/GaussianMorphMapBuilderWindow.cs`, `Editor/GaussianSplatting/GaussianSplatRendererEditor.cs`) — the package-side machinery for morphing between two `GaussianSplatAsset`s on a shared splat correspondence map. This target owns the package itself, not its consumers — the Timeline-side usage in the main project lives in the [[gaussian-morphing]] target (`KitchenOfMemories_Unity6` repo), which reaches this package only through the git package dependency, never by editing it directly.

## Why
`GaussianSplatMorpher` originally only supported a pair of assets assigned at edit time, with no public way for external code (a runtime Timeline mixer) to assign a *new* pair — `SwapAssets()` only swapped the existing one. This blocked [[gaussian-morphing]]'s morph-pair Timeline clip case for a full session until `SetAssets(left, right, map)` was added here, since the consuming project can't edit a git-URL package dependency directly; any fix has to land at this source repo first, then flow back via the existing dependency.

Two correctness bugs surfaced once `SetAssets` was actually exercised from Timeline: (1) `GaussianMorphMap` stored only splat counts, no asset identity — `MapIsSwapped()`'s count-based heuristic couldn't disambiguate orientation whenever both assets had equal/similar counts, causing morph playback to invert and the fix to not persist across clip restarts (`MapIsSwapped()` recomputes every `Setup()`, independent of any manual swap). Fixed by storing asset GUIDs on the map at build time and comparing by identity, falling back to the count heuristic only for legacy pre-fix maps. (2) `SetAssets`'s null-guard only checked `assetLeft`/`assetRight`, not `morphMap` — once the Timeline mixer started calling `SetAssets` with a partial set (assets assigned, map not yet built, to keep the morpher's Inspector fields in sync with clip authoring state), `Setup()` ran through to `BuildIndexBuffer()` → `MapIsSwapped()` and dereferenced the null map. Fixed by extending the same guard to all three fields, matching `OnEnable`'s existing all-three check.

A separate, unrelated editor bug was found and fixed alongside this work: `GaussianSplatRendererEditor.OnGetFrameBounds()` read `gs.asset.boundsMin`/`boundsMax` without checking `gs.asset` for null — while `GaussianSplatMorpher` has taken over a renderer via `SetExternalBuffers`, `gs.asset` is legitimately null (the renderer is driven by external buffers, not its own asset), and pressing Frame Selected (F) in that state threw `NullReferenceException` every time.

## Where
- `Runtime/GaussianSplatting/Morph/GaussianSplatMorpher.cs` — `SetAssets(left, right, map)` (public, added this cycle) is now the entry point for runtime asset-pair reassignment; mirrors `SwapAssets()`'s rebuild pattern (`ReleaseGpuResources()` + `Setup()`) when called while enabled with a valid new pair, tears down to idle (matching `OnEnable`'s null-guard) when any of the three is missing. `MapIsSwapped()` (called from `BuildIndexBuffer()` inside `Setup()`) resolves orientation by asset-GUID identity when the map carries one, falling back to splat-count comparison only for maps built before that field existed.
- `Runtime/GaussianSplatting/Morph/GaussianMorphMap.cs` — `leftAssetGuid`/`rightAssetGuid` string fields (added this cycle), set at build time via `AssetDatabase.AssetPathToGUID`. Empty on legacy maps.
- `Editor/GaussianSplatting/Morph/GaussianMorphMapBuilderWindow.cs` — `SaveAsset()` is the construction site that now stamps the GUID fields alongside the existing splat counts.
- `Editor/GaussianSplatting/GaussianSplatRendererEditor.cs` — `OnGetFrameBounds()`'s early-return guard now also checks `!gs.asset`, alongside the existing `!gs`/`!gs.HasValidRenderSetup` checks.
- GUID resolution in `MapIsSwapped()` is wrapped in `#if UNITY_EDITOR` (`AssetDatabase` is editor-only) — at runtime in a build this always falls through to the splat-count heuristic, unchanged from prior behavior there.
- Legacy `GaussianMorphMap` assets built before this fix have empty GUID fields and must be rebuilt via the Morph Map Builder window (`Tools > Gaussian Splats > Build Morph Map`) to get correct, identity-based orientation detection — the count heuristic remains the fallback for any map not yet rebuilt.
