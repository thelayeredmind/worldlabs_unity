# Perspective — Context

## What
A "Reproject" Inspector tool on `GaussianSplatRendererEditor` that lets the user take an already-selected set of splats and push/pull them along a per-splat axis toward/away from a chosen viewpoint, while resizing each splat so its apparent (projected) size from that viewpoint stays constant. Viewpoint has two modes — live SceneView camera (lockable — see below) and target Transform. Editor tool, not a runtime/render-path feature — distinct in nature from the `performance` target's GPU pipeline work. Feature-complete as of session 1's close: all planned units (kernel/plumbing, drag-slider UI, undo, apparent-size resize, camera-lock) delivered and user-verified.

## Why
Gaussians can be heavily camera-locked — splats that only look correct from one specific viewing angle (e.g. flattened/billboard-like splats from a limited-capture region). Reproject lets an artist correct/adjust these by moving them along their natural viewpoint axis without visually changing their apparent size, rather than needing to re-capture or manually eyeball a fix.

## Where
- `Shaders/SplatUtilities_DeviceRadixSort.compute` — `CSReprojectSelection` kernel (DeviceRadixSort-only, matching the existing `DeleteSelectedWithParams`/`BrushSelect`/`BrushSelectWorld` FidelityFX-asymmetry precedent). Reads `_SplatPosMouseDown` (drag-start position baseline) and `_SplatOtherMouseDown` (drag-start scale/rotation baseline, added this session — reuses the pre-existing global declared near `CSRotateSelection`, do not redeclare). Computes per-splat axis from `_ViewpointPos` to each splat's drag-start position; moves position along that axis by an amount parameter; when `scaleFmt == VECTOR_FMT_32F && shFormat == VECTOR_FMT_32F`, also rescales the splat's own packed scale (`_SplatOther`, at `otherAddr + 4`) by `newDist/originalDist` (perspective-only apparent-size-preserving ratio) — mirrors `CSRotateSelection`'s existing write pattern into `_SplatOther`. Gated on `IsSplatSelected(idx)`, dispatched over `m_SplatCount`. Position write requires 32F position format (same hard-gate as `CSTranslateSelection`/`CSScaleSelection`); scale write is a second independent guard. Non-32F packed scale formats (Norm16 etc.) are out of scope — moot in practice since `GaussianTool.CanBeEdited()` already restricts the whole edit suite to `chunkDataSize == 0` assets, which per the quality-tier table are already all-Float32.
- `Runtime/GaussianSplatting/GaussianSplatRenderer.cs` — `EditReprojectSelection(viewpointPos, l2w, w2l, amount)` C# wrapper (mirrors `EditScaleSelection`'s shape), dispatches `CSReprojectSelection`, requires both `m_GpuEditPosMouseDown` and `m_GpuEditOtherMouseDown` snapshots before dispatching, calls `UpdateEditCountsAndBounds()` after. `SnapshotPosData()`/`RestorePosData(byte[])` and `SnapshotOtherData()`/`RestoreOtherData(byte[])` — GPU↔CPU byte-array snapshot/restore pairs for the position and other (rotation+scale) buffers, used as undo baselines (mirrors `SnapshotDeletedBits`/`RestoreDeletedBits`'s pattern but for float data instead of bitmasks). `KernelIndices` enum has a `ReprojectSelection` entry — must stay ordinally in sync with the `.compute` file's `#pragma kernel` order (both DeviceRadixSort and FidelityFX files, even though Reproject itself is DeviceRadixSort-only — inserting a kernel shifts every later kernel's ordinal in both files if not added consistently).
- `Editor/GaussianSplatting/GaussianSplatRendererEditor.cs` — "Reproject" Inspector section (named "Reproject" in UI; target is named "Perspective" internally), placed after the Mask section. Viewpoint-mode popup (SceneView Camera / Target Transform) + conditional Transform object field. `ReprojectDragControl(gs)` — custom IMGUI horizontal-click-drag control (unbounded, no fixed range) replacing an earlier stopgap amount-FloatField+Apply-button pair. MouseDown: force-resets `m_ReprojectDragStartAmount`/`m_ReprojectAmount` to 0 unconditionally, snapshots pos+other data (`SnapshotPosData`/`SnapshotOtherData`) for undo, calls `gs.EditStorePosMouseDown()`/`EditStoreOtherMouseDown()` once as the drag-start baseline. MouseDrag: maps horizontal pixel delta through a quadratic curve (`sign(dx) * dx^2`, pixelsPerUnit=100) onto `m_ReprojectAmount`, dispatches `EditReprojectSelection` live every frame against the fixed drag-start baseline (never re-snapshots mid-drag), reading `_ViewpointPos` from `m_ReprojectLockedViewpointPos` when locked instead of resampling `SceneView.lastActiveSceneView.camera` live. MouseUp: pushes the pre-drag pos+other snapshot onto `s_ReprojectUndoStack`, resets `m_ReprojectAmount` to 0, clears drag state. Control renders as a 28px-tall solid rect, greyscale brightness lerping from 0.22 (idle) toward 0.75 as `|amount|` approaches 5 while actively dragging — no separate baseline/highlight color. `s_ReprojectUndoStack` — static `Stack<(gs, posSnap, otherSnap)>`, one entry per completed drag; "Undo Reproject (N)" button pops and restores both buffers + re-runs `UpdateEditCountsAndBounds()`. Mirrors the pre-existing `s_DeleteUndoStack`/`PopDeleteUndo()` pattern exactly (that pattern is a custom button-driven stack, NOT hooked into Ctrl+Z/Unity's native Undo system). "Commit to Disk" clears both undo stacks.
- Camera-lock (SceneView Camera mode only, not a 3rd dropdown entry): `m_ReprojectViewpointLocked`/`m_ReprojectLockedViewpointPos` fields. "Lock Viewpoint"/"Unlock Viewpoint" button next to the dropdown, position-only snapshot (no rotation/projection — matches what the kernel consumes), turns the button's `GUI.backgroundColor` yellow while locked. Switching the dropdown to Target Transform auto-clears an active lock. `OnSceneGUI()` (new override — none existed in this editor class before this session) draws a yellow `Handles.ConeHandleCap` at the active viewpoint origin (locked cam position, or the Target Transform's position in that mode) aimed via `Quaternion.LookRotation` toward `gs.transform.TransformPoint(gs.editSelectedBounds.center)` — shared gizmo logic across both viewpoint modes, sized screen-space-constant via `HandleUtility.GetHandleSize`.
- Precedent code (read, not modified): `Shaders/SplatUtilities_FidelityFX.compute`'s `CSTranslateSelection`/`CSRotateSelection`/`CSScaleSelection` — the drag-start-snapshot-buffer → per-splat-delta → `IsSplatSelected` gate → dispatch-over-`m_SplatCount` pattern Reproject follows throughout. `GaussianSplatting.hlsl`'s `LoadAndDecodeVector` — decode-only, no encode-side function exists anywhere in this codebase (relevant if a future unit needs to write non-32F packed scale formats).
- `GaussianSplatMask`/Masking section (legacy `.claude/flow/masking.1.session.md`) — the UI placement/pattern precedent Reproject's Inspector section was modeled after (button-driven apply, own Inspector section after Mask).
