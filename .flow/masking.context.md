## What

`GaussianSplatMask` — a ScriptableObject storing an ordered list of named brush selections, each a snapshot of `m_GpuEditSelected` (sparse `int[] splatIndices`) paired with a float `weight` in [0,1]. A per-splat reveal system driven by a single `m_MaskT` parameter on the renderer. Not `GaussianCutout` (baked layer-range cutouts at import time). `GaussianSplatMask` is a **sub-asset of its target `GaussianSplatAsset`** (not a standalone `.asset` file) — one mask per splat asset, created via a "Create Mask" button in `GaussianSplatRendererEditor`'s Mask section (next to `m_Mask`, `m_MaskT` slider, keyframe dots).

## Why

The existing cutout system can't express free painted selections. The mask system enables animated progressive reveals: paint a selection, store it as a keyframe at a given weight, repeat. Timeline animates `m_MaskT`; the reveal curve emerges from all entries together. Vertex-stage application: mask weight multiplies `o.col.a`, NaN-culls below threshold — zero GPU fragment cost for masked-out splats.

A mask's `splatIndices` are meaningless without the specific `GaussianSplatAsset` they were painted against — coupling the mask as a sub-asset (rather than an independently-creatable standalone asset) prevents orphaned/mismatched masks and removes a manual two-step (create mask asset, then assign it) in favor of one button. The `[CreateAssetMenu]` standalone-creation path was removed entirely so there's no way to create a mask that isn't attached to an asset.

`splatIndices` is stored as raw bytes in a hidden `GaussianSplatMaskData` sub-asset rather than inline in the ScriptableObject, to avoid a full AssetDatabase reimport stall on every entry mutation at large splat counts. Lazy-loaded via a property reading `dataAsset.bytes` on first access after `OnAfterDeserialize` invalidates the cache (eager decode caused a load-order race).

`UpdateMaskBuffer` runs only when dirty; `SetMaskDirty` is deferred via `EditorApplication.delayCall` so it fires after `AssetDatabase.SaveAssets()` settles.

When a `GaussianSplatRenderer` has a mask assigned AND `m_MaskT == 0` at `OnEnable()` (i.e. it's authored to start fully hidden), its GPU resource init (buffer uploads, texture creation, sort-buffer setup) is deferred and spread across multiple frames via a time-budgeted coroutine (`UpdateRessourcesBudgeted()`) instead of paid synchronously in one — the splat isn't visible yet, so there's no urgency for its expensive first-frame init to complete immediately. A public `IsReady` bool reports readiness (`false` during the deferred load, `true` once complete) for external code — e.g. a Timeline gate — to check before starting to animate `m_MaskT` upward, avoiding a visual snap from stale/half-loaded state. Every other case (no mask, or `MaskT > 0` at `OnEnable`) keeps the original fully-synchronous `UpdateRessources()` path unchanged, `IsReady = true` immediately. This budgeted path is now Play-Mode-only (`Application.isPlaying` gated in `Initialize()`; see [[performance]] for the gating fix and the mirrored `UpdateRessources()` mask-buffer fix) — Edit Mode always takes the synchronous path regardless of mask state.

`UpdateRessourcesBudgeted()`'s mask handling was moved, after two rejected attempts, to build `m_GpuMaskWeights` (`UpdateMaskBuffer()`) as the LAST budget-respecting step of the coroutine itself, immediately before `IsReady = true` — not in a `finally` block (synchronous, un-budgeted, defeats the point for large splat counts) and not deferred to `Update()`'s dirty-flag path (races `IsReady`: Unity resumes a `yield return null` coroutine after that frame's `Update()` already ran but before that frame's render, so a dirty-flag-only signal leaves the renderer visible-but-unmasked for one full frame every time). This makes "mask applied" part of the same readiness gate as "GPU resources ready," rather than two independently-timed signals that can race each other.

`GpuSorting.Create()` (`Runtime/GaussianSplatting/GpuSorting.cs`) caches constructed `DeviceRadixSort`/`FidelityFxSort` sorter objects in a `static readonly Dictionary<ComputeShader, T>`, keyed by the `ComputeShader` asset — construction (`FindKernel()` ×4, `IsSupported()` ×4) depends only on the ComputeShader + SortType, never on the calling renderer, so every renderer using the same compute shader after the first pays no redundant driver-level kernel/support-query cost. Each `GpuSorting` instance still owns its own per-renderer sort-buffer state (`_drsSorterArgs`/`_ffxSorterArgs`) — only the shared, read-only sorter object itself is cached.

**Past**
- **(2026-08-10 to 08-13) Activation-cascade cost + mask-race, RESOLVED across several rounds.** Ported the 2026-08-06 mask-timing fix from a consumer project's resolved package copy into this repo's real source (`|| !gs.IsReady` gate on `GatherSplatsForCamera`'s exclusion check; `yield return null` as `UpdateRessourcesBudgetedInternal()`'s literal first statement, before any real work). PCVR profiling (from `performance`) then found `GaussianSplatRenderer.OnEnable()` itself still costing ~233-267ms self-time across N simultaneously-activating renderers, traced to `Initialize()`'s unconditional `UpdateSortingType()` call constructing a fresh `GpuSorting`/`DeviceRadixSort` (4× `FindKernel()` + 4× `IsSupported()` driver queries) per renderer regardless of masked state — fixed via the `GpuSorting.Create()` cache (see What/Where). Designed and implemented a cross-renderer activation scheduler (start ≤1 new renderer/frame, bounded by a concurrent-max) — went through several incorrect iterations before landing: a `m_PendingStart`-deferred-start attempt was tried and reverted (wrongly assumed `StartCoroutine()`'s call-site timing mattered; it doesn't — `StartCoroutine` always runs synchronously to its first yield regardless of which frame calls it, so only the coroutine's OWN first-yield placement, not the caller's timing, provides real deferral). Found and fixed a genuine mask-visibility race in the process: `SetMaskDirty()` alone (fired from the coroutine's `finally` block) left every renderer visible-but-unmasked for exactly one full frame after `IsReady` flipped true, because Unity resumes a `yield return null` coroutine after that frame's `Update()` already ran — the dirty flag couldn't get picked up until NEXT frame's `Update()`, one frame too late. A synchronous `UpdateMaskBuffer()` call in `finally` was tried and rejected (reintroduces an unbudgeted blocking cost for large splat counts, exactly the failure mode this design exists to avoid) — correct fix was moving the mask build into the coroutine's own budget-respecting sequence, immediately before `IsReady = true` (see What). Finally found the actual dominant remaining Update()-self-time cost: `Update()` had no top-level `!IsReady` early-return at all, so unrelated real per-frame work (asset-hash comparison, `ResolveCenterEyeCamera()`, sort-init check, mask-dirty check) ran unconditionally every frame for every renderer during the ENTIRE budgeted-load window, not just once — added the guard, user confirmed live this was the actual fix (the several earlier, more speculative mechanisms investigated first — deferred-start, GpuSorting cache, coroutine-resume-staggering — were each real but not the dominant cost; lesson recorded: when a cost shows as a method's own direct self-time rather than a child call, check for a missing top-level state guard on that method BEFORE investigating specific child work).

Separate bug from masking itself, still unfixed — blocks any future splat-count-change repro until resolved.
